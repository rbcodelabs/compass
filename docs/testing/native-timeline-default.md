# Native timeline as the sole renderer

This change supersedes the Compass-only dogfood selection. All authenticated
workspaces use `NativeTimeline` for `?view=timeline`. Board remains the initial
roadmap view. Historical `timelineEngine` query parameters are ignored, including
`timelineEngine=classic`; existing bookmarks keep their view and squad filter.

## Removed

- SVAR's `RoadmapGantt` loader and `RoadmapGanttChart` adapter.
- The classic-only scheduling dialog, which had no other callers.
- `@svar-ui/react-gantt` and its unused transitive packages.
- The workspace-ID cohort and native/classic switching links.

Native supplies Month/Quarter zoom and deterministic horizon/squad tracks. The
classic renderer's Day/Week/Year zoom and optional collapsible grouping controls
are not retained. The help page describes the available native controls.

## Data and recovery

Existing workspace authorization, roadmap actions, inclusive dates, and persisted
records are unchanged. This change has no schema migration or data conversion.
Controller regression tests cover acknowledged saves, stale responses, concurrent
panel edits, duplicate commands, rollback, and fresh-remount reconciliation.

The controller still retains mounted snapshots when records disappear from a
background response. It does not implement live multi-user synchronization.
`Reload timeline` starts a full page load to recover current server state, retaining
the URL and filters. It is disabled while an item or backlog save is pending.
Ambiguous concurrent changes disable editing of the affected item and show reload
guidance. Failed saves restore confirmed dates and announce failure.

There is no runtime classic-renderer fallback. Operational rollback requires
reverting this change and deploying the previous renderer selection; no data
migration or repair is needed.

## Verification coverage

- Route tests cover ordinary workspaces, old classic bookmarks, Board default,
  and remounting on squad changes.
- Component tests cover visible reload recovery and pending-save protection.
- Authenticated PostgreSQL browser tests cover desktop/mobile and dark/light
  appearance, ordinary-workspace selection, date edits and persistence, Board
  roundtrips, filters, pointer and keyboard move/resize, detail focus restoration,
  direct backlog placement, and a blocked-save rollback followed by reload.
- Documentation screenshots are regenerated by the authenticated suite under
  `public/screenshots/docs/native-timeline-*`.

Run the bounded browser suite with a dedicated output directory so Playwright
does not remove sibling verification logs:

```sh
pnpm test:e2e:roadmap -- --output=test-results/native-default-pw
```

The database runner requires a local `compass_e2e` database and verifies its
isolation sentinel and fixture cleanup. Never run it against production.

Physical iPhone behavior, true browser-UI 200% zoom, and production performance
were not revalidated by this renderer-removal change. Desktop/mobile browser
emulation does not substitute for those checks.

## Local verification evidence (2026-09-09)

- Full Vitest suite with two workers: 3,158 passed, 30 intentionally
  environment-gated tests skipped across 300 files. The skips require separate
  research/preview database or browser opt-ins, not native timeline fixtures.
- TypeScript: no errors. Full ESLint: no errors, 31 existing warnings.
- UI color and shared-primitive guards: passed.
- Authenticated isolated-PostgreSQL roadmap suite: 14 passed in 48.5 seconds,
  including direct backlog placement and failed-save rollback after reload.
  Cleanup verified zero fixture organizations and one isolation sentinel.
- Production build: passed. This is build evidence, not a production latency
  benchmark; authenticated browser tests use the local development server.
- Representative desktop/mobile, light/dark, and mobile date-editor screenshots
  were visually inspected. All 11 native documentation captures were regenerated.

The first full-suite attempts encountered a sandbox localhost permission failure
and an unrelated voice-probe 80ms deadline flake under host load. The isolated
voice-probe file passed all 26 tests, and the complete two-worker rerun passed.
Browser logs also retain a DnD-generated `aria-describedby` hydration-ID warning;
the change does not fix or claim to clear that existing native warning.

This is a local implementation for review, not a deployment approval. Physical
device/zoom evidence, independent review, CI, and explicit merge/release approval
remain release gates. With SVAR removed, rollback is deployment-based rather than
a workspace toggle.
